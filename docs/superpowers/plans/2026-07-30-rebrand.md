# TFLives Rebrand — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the entire visual system (colors, surfaces, motion) with a design built from the product spec (section 23) and 2026 market research, and remove the animated canvas background.

**Architecture:** Token-only rebuild — the theming mechanism (semantic CSS variables + `next-themes` class-based dark/light switching, established in the earlier Design Tokens work) stays. Only the *values* of the tokens change, plus a mechanical migration of every component still using the old hardcoded `tfl-*` palette classes over to the semantic tokens. The animated canvas background is deleted and replaced with a static CSS background.

**Tech Stack:** Next.js 15 App Router, Tailwind CSS 3, `next-themes`, `framer-motion` (already a dependency, used for scroll-reveal), CSS custom properties (HSL triplets, shadcn-style convention already in use).

## Global Constraints

- Color principal: azul en diferentes tonos; color secundario: blanco y neutros fríos (spec §23).
- Esquinas ligeramente redondeadas (spec §23) — no brutalist square, no exaggerated pill radius.
- Modos claro y oscuro completos y reales (spec §23, §24).
- Efectos de cristal/transparencia permitidos solo en superficies elevadas puntuales, no como textura global (design spec, sección "Superficies y materialidad").
- Ningún fondo animado corriendo de forma permanente; movimiento solo con propósito (scroll-reveal, hover, transiciones) (design spec, sección "Movimiento y fondo").
- Toda animación debe respetar `prefers-reduced-motion` (reglas del proyecto, sección 4).
- No hardcodear colores/tipografías/radios repetidos en componentes — usar los tokens (reglas del proyecto, sección 4).
- No usar `any` sin justificación; TypeScript estricto (reglas del proyecto, sección 3).
- Verificar en escritorio y móvil, claro y oscuro, antes de dar por terminada cualquier tarea visual (reglas del proyecto, sección 12).

### Task 3: Componente de scroll-reveal (movimiento con propósito)

**Files:**
- Create: `src/components/ui/reveal.tsx`

**Interfaces:**
- Produces: componente `Reveal` — `{ children: React.ReactNode; className?: string; delay?: number }`, exporta `default`. Envuelve contenido y lo anima con fade+slide al entrar en viewport, se salta la animación si `prefers-reduced-motion` está activo.
- Consumes: `framer-motion` (`motion`, `useReducedMotion` — ya es dependencia del proyecto, ver `package.json`).

- [ ] **Step 1: Crear el componente**

Crear `src/components/ui/reveal.tsx`:

```tsx
"use client";

import { motion, useReducedMotion } from "framer-motion";

interface RevealProps {
  children: React.ReactNode;
  className?: string;
  delay?: number;
}

export default function Reveal({ children, className, delay = 0 }: RevealProps) {
  const shouldReduceMotion = useReducedMotion();

  if (shouldReduceMotion) {
    return <div className={className}>{children}</div>;
  }

  return (
    <motion.div
      className={className}
      initial={{ opacity: 0, y: 16 }}
      whileInView={{ opacity: 1, y: 0 }}
      viewport={{ once: true, margin: "-80px" }}
      transition={{ duration: 0.5, delay, ease: "easeOut" }}
    >
      {children}
    </motion.div>
  );
}
```

- [ ] **Step 2: Crear el componente**

```tsx
export default function HeroGlow() {
  return (
    <div
      aria-hidden
      className="absolute inset-0 -z-10 flex items-center justify-center overflow-hidden motion-reduce:[&>div]:animate-none"
    >
      <div
        className="h-[420px] w-[420px] rounded-full bg-primary/20 blur-[120px] animate-glow-pulse"
      />
    </div>
  );
}
```

Esto es CSS puro compuesto por GPU (blur + opacity), sin canvas ni JS por frame — y la clase `motion-reduce:[&>div]:animate-none` de Tailwind desactiva la animación cuando el usuario tiene activada la preferencia de reducir movimiento del sistema.

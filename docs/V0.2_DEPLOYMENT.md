# v0.2.0 deployment and operations

The release extends the existing Post, Modality, TeamMember, admin guards, Markdown renderer, social interactions and next-intl messages. WikiArticle, WikiCategory and TimelineMilestone are the new content models. Existing post URLs and PATCH records remain valid; PATCH is displayed as a legacy changelog. Post publication state is derived from the existing published / archived / scheduledFor fields, avoiding a second competing state field.

## Database rollout

Back up the target Neon database before deploying. No reset or seed is required. The application needs the v0.2 migration **before** serving the new build.

This repository previously used `prisma db push` and had no migration history. The first migration records the exact previous schema; the second adds the release fields and models, backfills publication dates and modality slugs, and preserves posts, comments, reactions and team records.

For an **existing v0.1 database**, first compare its schema with the preserved baseline:

```powershell
npx prisma migrate diff --from-schema-datasource prisma/schema.prisma --to-schema-datamodel prisma/baseline.prisma --exit-code
```

Only if that comparison reports no differences (exit 0), mark the baseline as already applied, then deploy:

```powershell
npx prisma migrate resolve --applied 20260909000000_baseline
npx prisma migrate deploy
npm run db:generate
```

If the comparison finds drift, reconcile it before marking the baseline; do not blindly apply the baseline CREATE statements to populated tables. If the baseline has already been resolved, omit `migrate resolve`.

For a **new empty database**, run `npx prisma migrate deploy` directly. Both migrations are applied in order.

Existing modalities retain visibility and get unique `mode-…` slugs. Staff can edit those slugs and configure operational status/version/banner. New modes and content start unpublished. No production content is seeded by install or build.

## Vercel configuration

Keep the existing DATABASE_URL, BETTER_AUTH_URL, BETTER_AUTH_SECRET and any enabled auth/email provider configuration. Use the normal Node runtime; the Minecraft route explicitly uses Node.

Discord defaults to the required guild. DISCORD_SERVER_ID remains an optional override. To expose a public online count without a bot, enable the guild's Server Widget in Discord settings. DISCORD_BOT_TOKEN is optional; a bot with access to the guild enables approximate member/presence counts. Never expose that variable to the browser. Missing credentials or disabled widgets show unavailable statistics and retain the existing invite CTA.

Minecraft connects only to `mc.tflives.com:25565`, with a 3.5-second deadline and 30-second Next data cache. Durations measure the complete query, not ping latency. Counts are global, never invented for individual modes. Discord fetches have 2.5-second timeouts and five-minute revalidation. Home streams integrations independently using Suspense.

## Staff operation

Manage content at `/es/admin/posts`, `/es/admin/modalities`, `/es/admin/wiki`, `/es/admin/team`, `/es/admin/timeline` (or `/en/...`). Existing role rules remain: moderators manage posts and Wiki; administrators also manage modes, team and timeline. Every content endpoint checks the authenticated user's current database role.

The shared editor supports Markdown formatting, links, lists, headings, quotes and preview. Category management is part of the Wiki admin page. Optional ES/EN translations use the original field as fallback; translated text never overrides authorization or publication fields. Team social links and tags accept comma-separated values.

To schedule a post, enable Published and choose a future date. It stays private until that time. For Wiki, select Scheduled and a date. Publication visibility is evaluated on reads; no cron is needed. Scheduled publishing does not currently dispatch the existing instant-publication notifications automatically. Archive and delete require confirmation.

Editorial images use HTTPS URLs hosted by your existing media provider. Text editing requires no storage integration. The existing bounded profile-image database storage is unchanged; editorial image bytes are not stored in PostgreSQL.

## Validation

```powershell
npm install
npm run db:generate
npm run typecheck
npm run lint
npm test
npm run build
npm run test:integration
```

The integration suite uses a temporary in-memory PostgreSQL test database and local ports 55439/3109. It does not read or mutate the configured Neon database. It applies both migrations over populated legacy fixtures, starts the production build, signs up a temporary test account, verifies 401/403 and staff CRUD, and checks public visibility, translations, empty states and legacy URLs. Test data disappears when the process exits. Run it only after building.

Production dependencies retain the existing Better Auth / JOSE Edge warnings; the middleware only reads the session cookie and actual authorization stays server-side. Review existing npm audit findings separately from this release; no automatic breaking dependency upgrades are performed.
